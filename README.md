# HH Vacancy Closure Monitor

Production-ready веб-сервис для мониторинга закрытых вакансий "Финансовый директор" на hh.ru и выгрузки списка закрытых вакансий для дальнейшей B2B-коммуникации.

## Возможности

- 🔍 Автоматическое сканирование вакансий через HH API
- 📊 Определение закрытых вакансий (архивированные, удаленные, выведенные)
- 📧 Парсинг контактов с сайтов компаний (email, телефон)
- 🔒 Compliance режим для безопасной работы с данными
- 📥 Экспорт закрытых вакансий в CSV
- 📈 Мониторинг сканирований и статистика
- ⏰ Автоматическое ежедневное сканирование

## Технологии

- **Frontend**: Next.js 14 (App Router) + TypeScript + Tailwind CSS
- **Backend**: Next.js API Routes
- **База данных**: PostgreSQL + Prisma ORM
- **Очереди**: BullMQ + Redis
- **Планировщик**: node-cron
- **Логирование**: pino

## Быстрый старт

### Локальная разработка

1. **Клонируйте репозиторий и установите зависимости:**

```bash
npm install
```

2. **Настройте переменные окружения:**

```bash
cp .env.example .env
```

Отредактируйте `.env`:
```env
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/hh_monitor?schema=public"
REDIS_URL="redis://localhost:6379"
COMPLIANCE_STRICT=true
HH_USER_AGENT="HH-Vacancy-Monitor/1.0 (contact: support@example.com)"
SCAN_GRACE_HOURS=48
```

3. **Запустите PostgreSQL и Redis:**

```bash
# Используя Docker Compose
docker-compose up -d postgres redis

# Или локально установленные сервисы
```

4. **Настройте базу данных:**

```bash
npx prisma migrate dev
npx prisma generate
```

5. **Запустите приложение:**

```bash
# Терминал 1: Web сервер
npm run dev

# Терминал 2: Worker для сканирования
npm run worker:scan

# Терминал 3: Worker для обогащения контактов
npm run worker:enrichment

# Терминал 4: Cron планировщик
npm run worker:cron
```

6. **Откройте браузер:**

```
http://localhost:3000
```

### Docker Compose (Production-like)

```bash
docker-compose up -d
```

Сервисы будут доступны:
- Web: http://localhost:3000
- PostgreSQL: localhost:5432
- Redis: localhost:6379

## Использование

### 1. Создание профиля поиска

1. Перейдите на страницу "Настройки поиска" (`/profiles`)
2. Нажмите "Создать профиль"
3. Заполните параметры:
   - **Название**: Имя профиля
   - **Текст поиска**: По умолчанию "Финансовый директор"
   - **Регион (ID)**: 
     - 1 = Москва
     - 2 = Санкт-Петербург
     - Другие ID можно найти через API `/api/dicts/areas`
   - **Автоматическое сканирование**: Включить для ежедневного сканирования

### 2. Запуск сканирования

1. На странице профилей нажмите "Запустить скан"
2. Выберите период:
   - Последние 7/14/30 дней (HH API ограничение: максимум 30 дней)
   - Или кастомный диапазон дат
3. Нажмите "Запустить сканирование"

**Примечание**: Для исторических периодов > 30 дней используется накопленная база данных из предыдущих сканирований.

### 3. Просмотр результатов

1. Перейдите на страницу "Результаты" (`/results`)
2. Используйте фильтры:
   - Дата закрытия (от/до)
   - Статус (Архивирована, Удалена, Закрыта)
3. Просматривайте закрытые вакансии с контактами компаний
4. Экспортируйте данные в CSV

### 4. Мониторинг сканирований

На странице "Журнал сканов" (`/scan-runs`) отслеживайте:
- Время запуска и завершения
- Статус (завершено, выполняется, ошибка)
- Количество найденных/новых/закрытых вакансий
- Ошибки и длительность

## API Endpoints

### Профили

- `GET /api/profiles` - Список профилей
- `POST /api/profiles` - Создать профиль
- `GET /api/profiles/[id]` - Получить профиль
- `PUT /api/profiles/[id]` - Обновить профиль
- `DELETE /api/profiles/[id]` - Удалить профиль

### Сканирование

- `POST /api/scan/run` - Запустить сканирование
- `GET /api/scan-runs` - Список сканирований

### Результаты

- `GET /api/closed-vacancies` - Закрытые вакансии (с фильтрами)
- `GET /api/closed-vacancies/export` - Экспорт в CSV

### Справочники

- `GET /api/dicts/areas` - Список регионов (кэш 1 час)
- `GET /api/dicts/specializations` - Список специализаций (кэш 1 час)

## Compliance режим

По умолчанию `COMPLIANCE_STRICT=true`:

- ✅ Контакты с сайтов компаний (`COMPANY_SITE`) разрешены для использования
- ❌ Контакты из HH API (`HH`) помечаются как `restricted_usage=true` и не экспортируются
- 🔒 CSV экспорт содержит только разрешенные контакты
- ⚠️ UI показывает источник контакта для прозрачности

Для отключения строгого режима (не рекомендуется для production):
```env
COMPLIANCE_STRICT=false
```

## Алгоритм определения закрытых вакансий

1. **Вакансия обнаружена** → статус `OPEN`, создается событие `SEEN`
2. **Вакансия не встречается в выдаче** → проверка через `GET /vacancies/{id}`:
   - `archived=true` → статус `ARCHIVED`, `closed_at = last_seen_at`
   - `404/410` → статус `REMOVED`, `closed_at = last_seen_at`
   - Иначе, если не встречается несколько сканов подряд → статус `CLOSED_INFERRED`

3. **Grace period**: Вакансии проверяются на закрытие только если `last_seen_at < now - GRACE_PERIOD_HOURS` (по умолчанию 48 часов)

## Парсинг контактов

Система автоматически парсит контакты с сайтов компаний:

1. Получает `site_url` из данных работодателя
2. Проверяет популярные страницы: `/contacts`, `/contact`, `/about`, `/company`
3. Извлекает контакты:
   - **Email**: из `mailto:` ссылок (высокая уверенность)
   - **Email**: из JSON-LD структурированных данных (высокая уверенность)
   - **Email**: из schema.org микроразметки (высокая уверенность)
   - **Email**: из текста страницы (средняя/низкая уверенность)
   - **Телефон**: из текста страницы (средняя уверенность)

4. Дедуплицирует контакты, сохраняет источник и уверенность

## Rate Limiting

Система автоматически:
- Ограничивает частоту запросов к HH API (200ms между запросами)
- Обрабатывает 429 (Too Many Requests) с экспоненциальным backoff
- Ограничивает частоту запросов к сайтам компаний (таймауты, уважение robots.txt на уровне best-effort)
